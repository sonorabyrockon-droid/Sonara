SONORA 3.20 — Catalogue description, cache invalidation and multi-upload audit

1. Added persistent track descriptions to the schema and edit modal (maximum 2,000 characters).
2. Included description in both public catalogue reads and the Worker admin overview.
3. Fixed stale Admin snapshot behavior by forcing a fresh overview after editing or deleting a track; forced refreshes are queued if an overview request is already running.
4. Added server-side duplicate checks against the full database candidate set (up to 100 same-title candidates) before R2 upload.
5. Added a frontend batch lock to prevent concurrent multiple-upload runs.
6. Batch uploads continue per file, keep newly uploaded tracks in local duplicate-check state, reuse the duration discovered during metadata scanning, and reload catalogue/admin data once after the batch rather than after every file.
7. Existing limits remain 100 MB per audio file and 12 uploads per administrator per hour.

Deployment order: first run sql/sonora-3-20-music-description.sql in Supabase; then deploy GitHub Pages frontend and Cloudflare Worker.

Validation: local syntax, SQL text, asset-version and static source consistency checks are run on this package. A live Supabase/R2 integration test is not possible from this source-only session.
